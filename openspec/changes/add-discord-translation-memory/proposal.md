## Why

当前译文只保存在当前频道的页面内存中，刷新、切换频道或重启后无法回看，相同消息再次翻译也会重复调用模型。将成功译文保存为本地记录并优先复用，可以降低重复调用成本，并让用户按 Discord 服务器和频道回查原文、译文及来源。

## What Changes

- 仅覆盖已有的 Discord 网页版普通服务器文字频道；用户已确认本次不接入其他网站，私信、线程和论坛仍不在范围内。
- 保存成功译文、原文、目标语言、所用模型、翻译指令版本、翻译时间，以及关联的服务器、频道和原消息链接；保存在扩展本地，不云同步，不记录 API Key。
- 手动点击和自动翻译共用本地优先的处理链路：精确命中有效记录时直接展示，未命中才调用 OpenRouter；命中不要求密钥仍有效，不产生模型费用。相同请求的共享状态保持到结果保存结束，避免模型已返回但尚未落盘时重复计费。手动模式仍等待用户点击，不额外自动展示或请求未点选的消息。
- 同一原文、目标语言、模型和指令版本可跨 Discord 频道复用；不同来源分别保留关联。原文有变、语言/模型/指令版本不同均不命中；不做模糊或语义替换。
- 新增独立「翻译记录」页面，由 popup 进入；按词条首次生成时间从新到旧排列，最近使用时间仅展示；按服务器、频道、目标语言和模型筛选，搜索原文/译文，查看完整内容和原消息，删除单条词条或清空记录。复用和重译不改变现有词条的排序位置。
- 在 Discord 消息成功状态的操作菜单提供「重新翻译」，由用户显式触发并绕过缓存；使用当前消息正文与已保存翻译设置。重译和保存都成功后更新对应词条及当前译文，失败则保留原记录、原译文并显示原因，不要求先删除记录或刷新频道。
- 行内沿用现有紧凑样式；以按钮的简短状态及可访问说明区分记录命中，不新增占行卡片。翻译成功但记录写入失败时展示真实译文及明确的未保存状态，不能假称保存成功或再次调用模型掩盖错误。

## Capabilities

### New Capabilities

- `translation-memory`: 成功译文和来源的本地持久化、精确匹配、覆盖保存阶段的请求合并、显式重译的原子更新、删除语义以及存储错误暴露。
- `translation-history`: 独立记录页、来源筛选、搜索、详情、原消息导航和删除操作。

### Modified Capabilities

- `discord-message-translation`: 将普通翻译触发改为先查记录、未命中再调用模型；增加显式重译，保留手动/自动边界、消息生命周期和失败行为，允许无密钥时读取有效记录。
- `translation-settings`: 清除密钥保留翻译记录；配置和隐私文案区分本地复用与模型调用，增加记录页入口。
- `translation-interface`: 为记录复用、保存失败和重译菜单增加紧凑、可辨识的状态，继续沿用现有 design token。

## Impact

- 变更入口与共享契约：`entrypoints/background.ts`、`entrypoints/content.ts`、`entrypoints/popup/App.tsx`、`components/MessageTranslation.tsx`、`lib/messages.ts`、`lib/background-service.ts`、`lib/translation-state.ts`、`lib/discord-dom.ts`。
- 新增扩展本地 IndexedDB 记录仓库与 `entrypoints/history/` 独立页面；设置继续使用现有 `storage.local`。不增加服务端、云同步或浏览其他网站的权限。
- 既有设置与翻译流程须兼容；此前页面内译文没有持久数据，不能回溯补齐未保存的历史。记录页删除不修改 Discord 发言。
- 扩展现有 Vitest/jsdom 测试，增加真实存储契约、后台零网络命中、跨频道关联、并发与删除竞态和管理页集成验证；真实浏览器验收使用 ego lite。
- 规划依赖已完成的 `add-discord-message-translation`。其三份现有规格已先同步到 `openspec/specs/`，本变更的 delta 以这些基线为准；旧变更仍保留，未归档。
